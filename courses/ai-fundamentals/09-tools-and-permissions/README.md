# Validate a model-proposed tool call

[![Validate a model-proposed tool call](lesson.png)](https://aiml.sh/courses/ai-fundamentals/tools-and-permissions/)

Send a read tool schema to a local model, inspect one proposed call, and reject unknown names or invalid page arguments before the tool function runs.

- **Full lesson:** [https://aiml.sh/courses/ai-fundamentals/tools-and-permissions/](https://aiml.sh/courses/ai-fundamentals/tools-and-permissions/)
- **Reading time:** 11 min
- **Uses:** ollama 0.6.3 (Python client), pydantic 2.14.1, pytest 9.1.1, the gemma4:e2b model

## Lab

The [`lab/`](lab/) folder holds the complete runnable code, tests and recorded outputs, the same files as the lesson's download on aiml.sh. The lesson explains each step.

### Lab notes

#### Validate a model-proposed tool call

Download `/labs/tools-and-permissions.zip` and extract it. Keep the included fixtures and Python files together in `tools-and-permissions/`. Requires Python 3.12 or later.

##### Setup, tests and execution

From this directory:

```sh
python3.12 -m venv .venv
.venv/bin/python -m pip install -r requirements-lock.txt

#### Offline tests: no model calls
.venv/bin/python -m pytest -q

#### Run after reading the implementation below
ollama pull gemma4:e2b
.venv/bin/python single_call.py
```

The live commands contact Ollama or the hosted provider; the offline tests replace model calls. Run them from the extracted lab directory. Saved outputs describe earlier runs and are not regenerated by the offline tests.

Read `single_call.py` before its live run. Some drivers write their results next to the source; use a fresh extracted copy when comparing with the bundled recordings. The tests exercise the implementation with local fixtures or replaced model clients; passing them does not establish model quality.
